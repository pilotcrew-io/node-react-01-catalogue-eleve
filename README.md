# Retail · Un catalogue React accessible

**Atelier 01/06 · 4 h 30 · nr-01-catalogue**

Une équipe Retail veut rendre trente références fictives consultables. Les utilisateurs doivent comprendre si le catalogue charge, s’il est vide ou si une erreur permet de réessayer. Le premier incrément se concentre sur la page initiale ; le panier et les filtres interactifs arriveront ensuite.

Ce dépôt contient les instructions, les mémos et les espaces de travail. **Le code est à construire ; aucune solution terminée n’est fournie dans le dépôt élève.** Les acquisitions précédentes sont reprises avant la séance selon [Day 0](DAY0.md).

## À la fin de la séance

- Décrire le trajet d’un produit depuis la fixture serveur jusqu’au composant.
- Valider les paramètres HTTP et les données reçues à l’exécution.
- Construire des composants sémantiques et distinguer attente, vide et erreur.
- Produire des preuves du contrat et des interactions essentielles.

## Déroulé de 270 minutes

| Séquence | Minutes |
| --- | --- |
| Cadrage et contrat | 20 |
| API et données serveur | 55 |
| Validation et contrat HTTP | 55 |
| Composants et chargement React | 65 |
| Vérifications ciblées | 50 |
| Revue et remise | 25 |

Répartition cible de cette séance : **135 min frontend / 135 min backend**, tests et revue de chaque couche inclus. Sur le cursus : **18 h frontend et 9 h backend**. Cette dominante React est un choix pédagogique, pas un ratio chiffré attribué à l’annonce.
